# Roles in LLM APIs

## 🚀 Introduction

When interacting with LLMs, we use **roles** to define how messages are structured.

👉 Roles help the model understand:

* Who is giving instruction
* What is the context
* How to respond

---

## 🧠 Simple Intuition

Think of roles like a conversation:

* **System** → sets behavior
* **User** → asks question
* **Assistant** → gives answer

---

## 📌 Types of Roles

---

## 🔹 1. System Role

* Defines behavior of the model
* Sets instructions

### Example:

```text
You are a helpful AI assistant.
```

👉 Controls tone, style, and rules

---

## 🔹 2. User Role

* Input given by user

### Example:

```text
Explain machine learning
```

---

## 🔹 3. Assistant Role

* Response generated by model

### Example:

```text
Machine learning is a subset of AI...
```

---

## 🔄 Conversation Flow

```text
System → User → Assistant
```

---

## ⚙️ Example (OpenAI Style)

```python
from openai import OpenAI

client = OpenAI(api_key="API key here")

response = client.responses.create(
    model="gpt-4.1",
    input=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "What is AI?"}
    ]
)

print(response.output_text)
```

---

## ⚙️ Example (Gemini Style)

Gemini uses **system_instruction** inside configuration instead of explicit role-based messages.

```python
from google import genai
from google.genai import types

client = genai.Client(api_key="API key here")

response = client.models.generate_content(
    model="gemini-3-flash-preview",
    contents="What is AI?",
    config=types.GenerateContentConfig(
        system_instruction="You are a helpful assistant.",
        temperature=0.7
    )
)

print(response.text)
```

| Role      | Purpose           |
